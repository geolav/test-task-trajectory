# CRM sync

Точка входа: `main.collect_leads_customers(is_full=True)`. Целевая нагрузка: 20 000 покупателей и 50 000 сделок.

## Реализация

- Вместо JSONB-массивов используются `amo_customer`, `amo_lead`, `amo_contact` и `amo_company`. CRM ID - первичный ключ для покупателей и сделок; для контактов и компаний - составной ключ `(abc_id, crm_id)`. Поля `login` и `name` индексируются.
- `abc_id` связывает покупателя и его сделки. JSON payload сохраняется в `data` без изменения формата.
- Выгрузка читается один раз. Поиск выполняется пакетными `SELECT` по 5 000 значений, запись — `INSERT ... ON CONFLICT` пачками по 2 000 строк.
- Слияние переносит дочерние записи на агрегат сделки. При совпадении контактов или компаний сохраняются данные записи-жертвы.
- Контакты и компании этим проходом не upsert-ятся: собираются их ID для очистки, а сохранение выполняет другая часть приложения. При слиянии их строки переносятся на агрегат-приёмник.
- `send_methods` и фильтры инкрементального прохода сохранены. Удаление запускается только после успешного полного прохода.

## Оценка нагрузки

Для генератора на 20k/50k расчёт по размеру пачек даёт около 78 SQL-команд: 24 `SELECT`, 39 `INSERT`, 2 `UPDATE`, 13 `DELETE`; около 38 commit. Это оценка структуры запросов, а не замер на целевой БД.

Сериализованный payload генератора - около 74 МБ. Оценка Python-структур (payload, карты соответствий и строки upsert) - около 240-270 МБ; фактический пик зависит от драйвера и окружения. `scripts/benchmark_load.py` измеряет время, SQL-команды, commit и пик Python heap через `tracemalloc`.

## Проверка

Нужны Python 3.9+ и PostgreSQL.

```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest tests/ -q
python scripts/benchmark_load.py
```

`TEST_DATABASE_URI` задаёт БД для тестов, `DATABASE_URI` - для бенчмарка. Оба набора тестов и бенчмарк пересоздают таблицы; используйте отдельные тестовые базы.

В тестовом наборе 27 сценариев: правила поиска и слияния, очистка, прерывание выгрузки, формат payload и ограничение числа SQL-команд. CRM API заменён генератором тестовых данных.

Миграция старой схемы: `migrations/upgrade.sql`. Перед запуском сохраните резервную копию БД.
